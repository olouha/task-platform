## 二、分支策略

### 2.1 分支命名规范

```bash
# 功能分支
feature/frontend-price-page      # A：前端价格页面
feature/backend-price-api        # B：后端价格API
feature/backend-price-scraper    # B：价格抓取
feature/test-ci-cd              # C：测试和部署

# 修复分支
bugfix/fix-price-calc          # 修复调差计算bug
bugfix/fix-scraper-error        # 修复抓取错误

# 发布分支
release/v1.0.0                  # 发布版本
```

### 2.2 创建分支

```bash
# 每人从 dev 创建自己的分支
git checkout dev
git pull origin dev
git checkout -b feature/你的名字-功能名

# 示例
git checkout -b feature/a-price-page      # A 创建前端分支
git checkout -b feature/b-backend-api      # B 创建后端分支
git checkout -b feature/c-test-deploy      # C 创建测试分支
```

## 三、代码整合流程

### 3.1 每日整合流程

```bash
# ===== 每天开始工作前 =====
# 1. 拉取最新代码
git checkout dev
git pull origin dev

# 2. 合并到自己的分支
git checkout feature/a-price-page
git merge dev

# ===== 每天结束前 =====
# 3. 推送自己的代码
git add .
git commit -m "feat: 完成价格页面表格"
git push origin feature/a-price-page

# 4. 提交 MR/PR 请求
# 在 GitHub 网页上创建 Pull Request
```

### 3.2 代码整合时间表

| 时间 | 动作 | 负责人 |
|------|------|--------|
| 每天 9:00 | 拉取最新 dev | 所有人 |
| 每天 18:00 | 提交代码到自己的分支 | 所有人 |
| 每天 19:00 | 合并到 dev | A/B 互审 |
| 每周五 | 合并 dev → release | C |

```bash
# 2. 开发完成后，提交代码
```

```bash
git push origin feature/b-backend-api

```

### 4.3 合并到 dev（定期）

```bash
# 假设 A 和 B 都要合并
# 在 GitHub 上操作：

# PR 1: feature/a-price-page → dev
```

## 五、冲突解决

### 5.1 常见冲突场景

```
场景1：A 和 B 同时修改同一个文件
场景2：前端依赖的 API 还没合并，后端先提交
场景3：多人修改同一个 API 路由
```

### 5.2 冲突解决步骤

```bash
# 1. 假设合并时发生冲突
git merge dev
# Auto-merging src/pages/Dashboard.tsx
# CONFLICT (content): Merge conflict in src/pages/Dashboard.tsx

# 2. 查看冲突文件
git status
# both modified: src/pages/Dashboard.tsx

# 3. 打开文件，冲突标记如下
<<<<<<< HEAD
    // A 的代码
    const priceData = usePriceData();
=======
    // B 的代码
    const priceData = usePriceDataV2();
>>>>>>> dev

# 4. 手动解决冲突（协商决定保留哪个）
# 选择保留的代码，删除 <<< === >>> 标记

# 5. 标记解决
git add src/pages/Dashboard.tsx

# 6. 提交
git commit -m "merge: 解决 Dashboard.tsx 冲突"
```

### 5.3 避免冲突的建议

| 建议 | 说明 |
|------|------|
| 模块化开发 | 每人负责不同的文件/模块 |
| 及时同步 | 每天开始前拉取最新代码 |
| 提前沟通 | 修改公共文件前先告知 |
| 频繁提交 | 小步提交，容易追溯 |

## 六、CI/CD 自动整合

### 6.1 GitHub Actions 配置

创建 `.github/workflows/ci.yml`:

```yaml
name: CI/CD

on:
  push:
    branches: [dev, main]
  pull_request:
    branches: [dev, main]

jobs:
  # 前端检查
  frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: '18'
          cache: 'web/frontend'

      - name: Install dependencies
        run: cd web/frontend && npm install

      - name: Lint
        run: cd web/frontend && npm run lint

      - name: Type check
        run: cd web/frontend && npx tsc --noEmit

      - name: Build
        run: cd web/frontend && npm run build

      - name: Test
        run: cd web/frontend && npm test

  # 后端检查
  backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.10'

      - name: Install dependencies
        run: cd web/backend && pip install -r requirements.txt

      - name: Lint
        run: cd web/backend && pip install flake8 && flake8 .

      - name: Test
        run: cd web/backend && pip install pytest && pytest
```

### 6.2 自动合并条件

```yaml
# 在 PR 设置中启用
# Require status checks to pass before merging ✓
# Require branches to be up to date before merging ✓
```

### 6.3 部署触发

```yaml
# 只有合并到 main 时部署
on:
  push:
    branches: [main]

jobs:
  deploy:
    if: github.ref == 'refs/heads/main'
    steps:
      - name: Deploy to Vercel
        run: npx vercel --prod
```

```bash
# ===== A（前端）=====
git checkout -b feature/a-price-page
# 开始开发...

# 开始开发...

# ===== C（测试）=====
git checkout -b feature/c-test

```

### 第三天（整合）

```bash
# ===== B 先合并（前端依赖后端）=====
# GitHub 上创建 PR: feature/b-backend-api → dev
# Review 通过后合并

# ===== A 后合并 ======
git checkout dev
git pull origin dev
git checkout feature/a-price-page
git merge dev  # 可能需要解决冲突

# GitHub 上创建 PR: feature/a-price-page → dev
# Review 通过后合并

# ===== 所有人同步 ======
git checkout dev
git pull origin dev
```

### 遇到冲突怎么办

```bash
# 场景：同时修改了同一个文件
git merge dev
# CONFLICT: src/pages/Dashboard.tsx

# 解决冲突
# 1. 打开文件，手动编辑
# 2. 保留需要的代码
# 3. git add + git commit
# 4. 通知其他相关人员
```
