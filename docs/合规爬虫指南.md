## 一、合规措施

### 1.1 已实现的合规措施

| 措施 | 说明 | 效果 |
|------|------|------|
| ✅ 访问频率限制 | 每小时最多30次，每次间隔2分钟 | 不对服务器造成压力 |
| ✅ 表明身份 | User-Agent 包含用途和联系方式 | 网站可联系协商 |
| ✅ 自动重试 | 失败后等待5分钟重试，最多3次 | 避免频繁请求 |
| ✅ 错误处理 | 遇到问题自动停止 | 不会持续攻击 |
| ✅ 记录日志 | 所有请求都有日志 | 可追溯审计 |

### 1.2 合规请求头示例

```http
User-Agent: TaskPlatform-PriceFetcher/1.0
  (purpose: 工程调差计算系统，用于内部成本分析;
   contact: contact@yourcompany.com)
```

## 五、风险应对

### 5.1 收到网站警告

```python
# 如果收到 403 或 警告页面，立即停止

def fetch_with_warn_check(self, response):
    if response.status_code == 403:
        logger.error("❌ 被禁止访问，停止抓取")
        logger.error("请联系网站获取授权")
        return None

    if "访问过于频繁" in response.text:
        logger.error("❌ 触发频率限制，停止抓取")
        return None
```

## 六、法律建议

### 6.1 低风险行为

- ✅ 遵守 robots.txt
- ✅ 控制访问频率
- ✅ 表明身份和用途
- ✅ 仅用于内部分析
- ✅ 标注数据来源

### 6.2 高风险行为

- ❌ 绕过登录/验证码
- ❌ 大量并发请求
- ❌ 伪装成浏览器
- ❌ 抓取后公开传播
- ❌ 商业销售抓取的数据

### 6.3 如果被起诉

即使技术上可以爬取，也不意味着可以爬取。请：

1. **立即停止** - 收到任何警告都停止
2. **保存日志** - 记录自己的合规措施
3. **咨询律师** - 法律问题需要专业意见
4. **联系和解** - 多数网站愿意协商
