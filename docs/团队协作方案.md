# TaskPlatform 团队协作方案
## 使用 Claude Code 分配任务

---

## 一、团队分工

### 角色分配

| 角色 | 姓名 | Claude Code 使用方式 | 职责 |
|------|------|----------------------|------|
| 前端负责人 | A | 主会话 | UI开发、组件、图表 |
| 后端负责人 | B | 主会话 | API开发、定时任务、数据库 |
| 测试/运维 | C | 主会话 | 测试用例、部署、监控 |

### 分工原则

```
A（前端）←→ B（后端）←→ C（测试）
     ↓            ↓           ↓
  React组件    FastAPI      自动化测试
  Ant Design   Supabase     部署脚本
  图表        价格抓取     监控告警
```

---

## 二、Claude Code 使用方式

### 2.1 团队成员如何连接 Claude Code

每个团队成员在自己的电脑上：

1. **克隆代码仓库**
   ```bash
   git clone https://github.com/你的用户名/taskplatform.git
   cd taskplatform
   ```

2. **启动 Claude Code**
   ```bash
   claude
   ```

3. **设置项目上下文**
   - Claude Code 会自动读取当前项目
   - 可以通过 CLAUDE.md 设置项目规范

### 2.2 如何分配任务

#### 方法1：任务卡片式分配

```
负责人：A（前端）
任务：实现价格监控页面
截止：2026-05-15

Claude Code 指令：
"你是前端开发，负责实现价格监控页面
页面包含：
1. 最新价格表格（实时数据）
2. 分时段趋势图（可选择日/周/月/年）
3. 价格来源配置
参考：web/frontend/src/pages/PriceMonitor.tsx"
```

#### 方法2：功能模块分配

| 模块 | 负责人 | CLAUDE.md 内容 |
|------|--------|----------------|
| 前端UI | A | CLAUDE.md - 前端规范 |
| 后端API | B | CLAUDE.md - 后端规范 |
| 价格抓取 | B | CLAUDE.md - 抓取规范 |
| 测试部署 | C | CLAUDE.md - 部署规范 |

## 三、项目 CLAUDE.md 配置

### 3.1 根目录 CLAUDE.md（团队共享）

```markdown
# TaskPlatform 项目规范

## 项目概述
工程调差计算系统，用于自动抓取价格并计算材料调差。

## 团队分工
- A：前端开发（React + Ant Design）
- B：后端开发（FastAPI + Supabase）
- C：测试运维

## 技术栈
- 前端：React 18 + Vite + Ant Design 5
- 后端：FastAPI + Python 3.10+
- 数据库：Supabase PostgreSQL
- 部署：Vercel + Cloudflare Workers

## 目录结构
web/
├── frontend/          # 前端（负责人：A）
│   ├── src/
│   │   ├── components/  # 公共组件
│   │   ├── pages/      # 页面（每人负责几个）
│   │   └── services/    # API调用
├── backend/           # 后端（负责人：B）
│   ├── api/            # API路由
│   ├── services/       # 业务逻辑
│   └── models/         # 数据模型

## 工作流程
1. 从 main 分支创建功能分支
2. 开发完成后提 PR
3. 其他人 Code Review
4. 合并到 main
5. C 执行自动化部署

## 代码规范
- 提交信息使用中文
- PR 需要描述改动内容
- 单元测试覆盖核心逻辑
```

### 3.2 前端负责人 CLAUDE.md（前端目录）

```markdown
# 前端开发规范（负责人：A）

## 职责
- UI组件开发
- 页面路由配置
- 与后端API对接

## 当前任务
- [ ] Dashboard 页面
- [ ] 价格监控页面
- [ ] 调差计算页面
- [ ] 响应式适配

## 开发规范
- 组件放在 src/components/
- 页面放在 src/pages/
- 使用 Ant Design 组件
- 图表使用 @ant-design/charts

## API调用
baseURL: http://localhost:8000
生产环境: https://api.taskplatform.com

## 禁止事项
- 不要修改后端代码
- 不要直接提交到 main 分支
```

### 3.3 后端负责人 CLAUDE.md（后端目录）

```markdown
# 后端开发规范（负责人：B）

## 职责
- API开发
- 数据库设计
- 价格抓取

## 当前任务
- [x] 数据库初始化SQL
- [ ] 材料管理API
- [ ] 价格历史API
- [ ] 调差计算API
- [ ] 价格抓取定时任务

## API规范
- RESTful 风格
- 响应格式：{success: bool, data: any, error: string?}
- 错误码：4xx 客户端错误，5xx 服务端错误

## 数据库表
- material_categories（材料分类）
- materials（材料）
- price_sources（价格来源）
- price_history（价格历史）
- projects（项目）
- adjustment_records（调差记录）

## 价格抓取来源
- 我的钢铁网：钢筋、混凝土
- 有色金属网：铝、铜、锌
- 信息价：各地造价站

## 禁止事项
- 不要修改前端代码
- 不要直接提交到 main 分支
```

### 3.4 测试运维 CLAUDE.md（根目录）

```markdown
# 测试运维规范（负责人：C）

## 职责
- 自动化测试
- CI/CD 配置
- 监控告警

## 当前任务
- [ ] 编写测试用例
- [ ] 配置 GitHub Actions
- [ ] 部署到生产环境
- [ ] 配置监控告警

## 部署流程
1. 前端：Vercel
2. 后端：Cloudflare Workers
3. 数据库：Supabase（无需部署）

## 监控指标
- API 响应时间 < 200ms
- 前端加载时间 < 3s
- 价格抓取成功率 > 95%

## 告警规则
- API 错误率 > 1%
- 价格抓取失败连续3次
- 数据库连接失败
```

## 四、每日协作流程

### 4.1 晨会（5分钟）

每人简单汇报：
```
A："价格监控页面完成了，正在做调差计算"
B："API 写完了，价格抓取还需要2天"
C："测试用例写了50%，明天开始部署"
```

### 4.2 任务分配（Claude Code）

**A 收到任务：**
```
继续开发调差计算页面，需要：
1. 创建 Adjustment 组件
2. 实现计算逻辑
3. 添加结果展示表格
参考：web/frontend/src/pages/Adjustment.tsx
```

**B 收到任务：**
```
继续开发价格抓取功能：
1. 我的钢铁网 CSS 选择器测试
2. 保存到 Supabase 数据库
3. 配置 Cloudflare Workers 定时任务
参考：web/backend/services/price_scraper.py
```

**C 收到任务：**
```
准备部署和测试：
1. 创建 GitHub Actions 配置
2. 编写前端测试用例
3. 配置 Vercel 部署
参考：.github/workflows/deploy.yml
```

### 4.3 Code Review

```bash
# A 完成后提 PR
git checkout -b feature/adjustment-page
git add .
git commit -m "feat: 添加调差计算页面"
git push origin feature/adjustment-page

# B 和 C Review PR
# 可以在 GitHub 上评论或 Slack 沟通
```

## 五、问题解决

### 5.1 遇到问题怎么办？

```
情况1：前端调用API报错
→ 找 B 检查 API 是否正常

情况2：价格抓取失败
→ 找 B 检查选择器是否失效

情况3：数据库连接失败
→ 找 B 检查 Supabase 配置

情况4：部署失败
→ 找 C 检查配置是否正确
```

### 5.2 紧急情况

```
Slack/微信群发消息：
"🔴 紧急：[问题描述] 需要谁处理"

负责人看到后立即处理
```
